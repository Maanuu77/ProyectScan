# ADR-0011: No AI; better texts from the code and from the user

- Status: accepted, supersedes ADR-0003 and ADR-0009
- Date: 2026-10-28

## Context

ADR-0009 made a local LLM (Ollama) optional, to translate names, describe undocumented features and write a summary. Most people who try the app would not install Ollama, and those who did would wait for a 2 GB download. Bundling a model would turn a 36 MB executable into more than 2 GB. The structure (apps, features, flows) never depended on the AI; only the wording did.

## Decision

Drop the AI. Every user gets the same full result from three deterministic sources:

1. **The code and the project itself**: OpenAPI tags, Javadoc and JSDoc, route titles, the `description` in `package.json` or `pom.xml`, and the first paragraph of the project's README.
2. **Generated sentences built from the analysis**, such as "2 screens: login and registro. Signs in with Firebase Auth.", which are always true.
3. **The user's own words**: names, descriptions and language can be edited in the app and are saved in `xray.toml`, so the next analysis keeps them.

The labels of the documents ("What is it made of?", "Entry point"…) exist in English and Spanish. The language is detected from the comments in the code and can be changed, so a Spanish project is documented in Spanish and an English one in English, without mixing.

## Consequences

- One small executable, no setup, identical results on every machine and no text that could be made up.
- Names stay in the language of the code unless the user edits them; automatic translation was ruled out (a dictionary gets "banco" wrong, online services cost money or send code out).
- The project is a static-analysis tool rather than an AI project.
